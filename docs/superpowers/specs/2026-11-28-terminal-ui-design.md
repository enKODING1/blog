# 블로그 UI/UX 개편: 터미널 OS 테마 + 인터랙션 설계

작성일: 2026-11-28

## 의도

블로그(`blog.skang.dev`, Next.js 15.5 App Router, Amplify SSR)는 기능은 갖췄지만 UI가 흰 바탕의 최소 뼈대뿐이다. 사용자는 "creativity한 UI/UX 블로그, 페이지 트랜지션이 있는 인터랙티브한 웹"을 원한다. 참고 사이트(edoardolunardi.dev)의 어두운 바탕·고정폭 타이포·레트로 OS 감성을 가져오되, 그 사이트를 베끼지 않고 이 블로그만의 **터미널 OS** 콘셉트로 만든다. 나중에 애니메이션을 더 넣을 예정이므로 그 기반도 깐다.

## 사용자가 고른 것 (시안 비교 후 결정)

- 방향: **A. 터미널 OS** (미술관 방향, 잉크 필드, 그리드 랩은 제외).
- 효과: **3. 텍스트 스크램블**, **5. 블록 커서**, **7. 상태 표시줄 읽기 진행도**.
- 페이지 전환: **B. 지우고 다시 타이핑(`clear`)**.
- 구현 방식: **방법 1. 전환 링크 컴포넌트가 순서를 제어하고 애니메이션은 GSAP**.

## 목표

- 공개 페이지(`/`, `/posts/[slug]`, 404)를 터미널 OS 테마로 새로 디자인한다.
- 위 세 효과와 B 전환을 넣는다.
- 키보드만으로 글 목록을 탐색할 수 있다 (A 시안에 포함된 요소).
- 관리자 화면(`/admin/**`)은 같은 어두운 테마 색·글꼴만 적용한다 (효과 없음).
- 이후 애니메이션을 추가하기 쉬운 구조(GSAP 기반, 전환·등장 훅이 한곳에 모임).

## 비목표

- 라이트 테마·테마 전환, 사운드, WebGL 배경, 부팅 시퀀스, CRT 전환, 배경 잡음/빛 띠(1·2·4·6번 효과는 고르지 않음).
- 검색, 태그 필터, 댓글.
- 데이터·인증·인프라 변경 (이번 작업은 프런트엔드만).

## 안티 목표 (동작해도 실패인 것)

- 전환 때문에 글을 여는 데 1초 넘게 기다리는 것 (전환 전체 ≤ 0.8초).
- 뒤로 가기·새 탭 열기(⌘/Ctrl/Shift/가운데 클릭)·링크 복사가 평범한 링크처럼 동작하지 않는 것.
- "동작 줄이기"를 켠 사용자에게 움직임이 보이는 것.
- 터치 기기에서 블록 커서가 보이거나 탭이 늦게 반응하는 것.
- 한글 본문이 고정폭 글꼴 때문에 읽기 불편해지는 것.
- 레이아웃이 애니메이션 중에 밀리는 것 (CLS).
- 스크린 리더가 스크램블 중인 무작위 기호를 읽는 것.
- 검색엔진·SNS 미리보기가 빈 페이지나 기호를 보는 것 (SSR HTML에는 원래 텍스트가 그대로 있어야 함).

## 제약

- Next.js 15.5.29, React 19.3.1, Tailwind 4 (현재 저장소 그대로).
- 공개 페이지는 서버 컴포넌트로 데이터를 읽는 현재 구조 유지(`force-dynamic`, DynamoDB). 효과는 클라이언트 컴포넌트로 감싼다.
- GSAP(+ `@gsap/react`의 `useGSAP`, ScrambleTextPlugin). GSAP는 현재 모든 플러그인이 무료.
- 기존 Global Constraints 유지(코드 스타일 `.prettierrc`, CI `Lint / Build`·테스트, AWS env 없이 빌드 통과).
- main에 바로 push하면 Amplify가 배포한다 → 로컬과 CI에서 충분히 확인한 뒤 push.

## 접근 방식

| 방법                           | 내용                                                                                                                    | 장점                                              | 단점                                                     |
| ------------------------------ | ----------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------- | -------------------------------------------------------- |
| **1. 전환 링크 + GSAP (선택)** | `TransitionLink`가 클릭을 가로채 줄 단위 퇴장 애니메이션 후 `router.push`, 새 페이지는 등장 애니메이션. GSAP로 타임라인 | B 전환을 정확히 구현, 나중 애니메이션도 같은 도구 | 번들 약 +70KB, 이동 순서를 직접 관리                     |
| 2. 같은 구조, CSS + 직접 짠 JS | 라이브러리 없음                                                                                                         | 가장 가벼움                                       | 효과가 늘수록 직접 코드가 커짐                           |
| 3. View Transitions API        | Next 실험 기능                                                                                                          | 코드 최소                                         | 이전 화면을 사진으로 넘겨 줄 단위 지우기 불가, 실험 기능 |

## 설계

### 시각 언어

- 색 토큰(CSS 변수, Tailwind 4 `@theme`):
  - `--bg #1c1c1c`, `--fg #e8e8e8`, `--dim #8a8a8a`, `--line #333`, `--accent #54fcfc`(상태·성공), `--error #ff5f57`.
  - 선택·강조는 **반전**(배경 `--fg`, 글자 `--bg`).
- 글꼴:
  - 화면 틀(상태 표시줄, 목록, 메타, 버튼, 입력)은 고정폭: JetBrains Mono(`next/font/google`), 한글은 시스템 고정폭/산세리프로 폴백.
  - 글 본문(`prose`)은 한글 가독성을 위해 산세리프(Noto Sans KR 또는 시스템), 코드 블록만 고정폭.
- 화면 위에 아주 옅은 주사선 오버레이(고정, `pointer-events: none`). 동작 줄이기와 무관한 정적 효과.
- 코드 하이라이트는 어두운 테마(현재 github-dark 스타일시트 유지, 라이트 스타일시트 제거).

### 레이아웃 (공개)

```
┌ 상태 표시줄 (고정, 상단) ───────────────────────────────────────┐
│ seongjin@blog ~/posts/minishell        [#####-----] 50%  ● 22:14 KST │
└──────────────────────────────────────────────────────────────────┘
  $ ls posts --sort=date
  2025-12-01  WEB  브라우저가 렌더링 하는 과정        ← 선택된 줄은 반전
  2025-08-21  CS   부동 소수점을 고정 소수점 방식으로 다루기
  ...
┌ 키 안내 (하단, 포인터 장치에서만) ─────────────────────────────┐
│ [J][K] 이동   [↵] 열기   [esc] 목록으로                           │
└──────────────────────────────────────────────────────────────────┘
```

- 상태 표시줄: 왼쪽 `seongjin@blog ~` + 현재 경로(`~/posts/<slug>`), 오른쪽에 글 페이지에서만 읽기 진행도, 그리고 `●` + 서울 시각 `HH:mm KST`(분 단위 갱신). SSR 시점엔 시계 자리 `--:--`로 렌더해 hydration 불일치 방지.
- 목록(`/`): `$ ls posts --sort=date` 프롬프트 줄 + 한 줄에 날짜·카테고리·제목(격자 정렬). 마우스 올림 또는 키보드 선택 시 줄 반전.
- 글(`/posts/[slug]`): `$ cat posts/<slug>.md` 프롬프트 줄, 제목(큰 글씨), `날짜 · 카테고리`, 본문 `prose`(어두운 테마). 하단에 `← cd ..` 목록으로 링크.
- 404: `bash: <경로>: command not found` + `← cd ~` 링크.
- 모바일(좁은 화면): 목록 줄은 날짜·카테고리를 위, 제목을 아래로 두 줄. 키 안내 숨김. 상태 표시줄은 경로를 줄여 말줄임.

### 효과

1. **텍스트 스크램블 (3)**
   - 목록 줄 제목: 마우스 올림 또는 키보드 선택 시 0.4초 스크램블 후 원래 글자.
   - 글 제목: 페이지 등장 시 한 번.
   - 원본 텍스트는 SSR에 그대로 있고, 스크램블 동안 요소에 `aria-label`(원문)과 시각용 텍스트는 `aria-hidden` 처리해 스크린 리더가 기호를 읽지 않게 한다.
   - 기호 집합: `!<>-_\/[]{}=+*^?#01` (한글 자모 섞지 않음).
2. **블록 커서 (5)**
   - `pointer: fine` 이고 동작 줄이기가 꺼진 경우에만. 네이티브 커서는 공개 페이지에서만 숨기고, 링크·텍스트 위에서도 블록 커서 유지(`mix-blend-mode: difference`로 글자 반전).
   - 잔상 블록이 0.25초 늦게 따라옴(GSAP `quickTo`).
   - 입력 요소(관리자, 텍스트 선택 시)에는 네이티브 커서 유지 — 관리자 화면에는 블록 커서 없음.
3. **읽기 진행도 (7)**
   - 글 페이지에서 본문 스크롤 비율을 상태 표시줄에 `[#####-----] 50%`(10칸)로 표시. `requestAnimationFrame`으로 스로틀.
   - 본문이 화면보다 짧으면 `100%`.

### 페이지 전환 B (`clear` → 타이핑)

- 대상: 공개 페이지 간 이동(`/` ↔ `/posts/*`, 404에서 홈).
- **퇴장**: `TransitionLink` 클릭 → 현재 `main` 안의 "줄"(`data-line` 표시된 요소들)을 위에서부터 40ms 간격으로 숨김(최대 300ms까지만, 넘치면 나머지 한 번에). 끝나면 `router.push(href)`.
- **등장**: 새 페이지 `main`의 `data-line` 요소들이 위에서부터 타이핑되듯 나타남(clip-path 또는 폭을 `steps()`로, 줄당 120ms, 줄 간 40ms, 최대 500ms). 글 제목은 이때 스크램블.
- 전체 길이 ≤ 0.8초. 등장은 상태 표시줄을 제외한 `main` 영역만.
- `router.prefetch(href)`를 마우스 올림/키보드 선택 때 호출해 퇴장 동안 데이터를 미리 받는다.
- 브라우저 뒤로/앞으로, 직접 주소 입력, 새로고침: 퇴장 없이 등장만.
- 수정키 클릭(⌘/Ctrl/Shift/Alt), 가운데 클릭, `target=_blank`, 외부 링크, 같은 경로: 가로채지 않음.
- 전환 중 다른 링크 클릭: 진행 중 퇴장을 즉시 끝내고 새 목적지로.
- 이동 후 포커스는 새 페이지의 첫 제목으로(접근성), 스크롤은 맨 위.

### 키보드 탐색

- 목록에서 `j`/`↓` 다음, `k`/`↑` 이전, `Enter` 열기(전환 B 사용), 첫 진입 시 선택 없음 → 첫 키 입력에 첫 줄 선택.
- 글에서 `Esc` 또는 `Backspace`(입력 중이 아닐 때) → 목록으로.
- 선택된 줄은 화면 안으로 스크롤.
- 입력 요소 포커스 중에는 단축키 무시.

### 동작 줄이기 · 접근성

- `prefers-reduced-motion: reduce`: 전환·스크램블·커서 잔상 모두 끔(즉시 이동, 원문 표시). 진행도와 주사선은 유지.
- 모든 상호작용 요소는 키보드 포커스 표시(반전 테두리).
- 색 대비: `--dim #8a8a8a` on `#1c1c1c`는 본문이 아닌 메타 텍스트에만.

### 구조 (구현 지침)

- `src/app/layout.tsx`: 글꼴·색 토큰, 주사선, 상태 표시줄, 블록 커서, 전환 컨텍스트 제공. GA 유지.
- 클라이언트 컴포넌트(새 폴더 예: `src/app/_terminal/`): `TransitionProvider`/`TransitionLink`, `PageEnter`(등장 애니메이션), `Scramble`, `BlockCursor`, `StatusBar`(경로·시계·진행도), `KeyboardNav`.
- 공개 페이지는 서버 컴포넌트 유지, 줄 요소에 `data-line` 표시, 링크는 `TransitionLink`.
- 관리자 레이아웃은 블록 커서·전환을 쓰지 않음(경로 기준으로 끔).
- GSAP 플러그인 등록은 클라이언트 한곳에서.

## 제 판단으로 정한 것 (사용자 확인 필요)

- 한글 본문은 산세리프, 화면 틀만 고정폭.
- 키보드 탐색(J/K/Enter/Esc) 포함 — A 시안 요소. 테마 전환 키(T)는 제외.
- 주사선 오버레이 포함 — A 시안 요소(정적, 아주 옅게).
- 시계는 서울 시각 `KST`.
- 404 문구 `command not found`.
- 관리자는 색·글꼴만.

## 구현자에게 맡기는 것

- 정확한 글꼴 조합(JetBrains Mono 외 대안 가능, 한글 폴백).
- 애니메이션 세부 이징·간격(위 상한 안에서).
- 컴포넌트 파일 분할.
- 테스트 방식(순수 로직은 단위 테스트, 상호작용은 수동 확인 목록).
